# 灰度循迹设计方案

## 一、硬件布局

五路灰度传感器，按车体从左到右排列。根据实测资料：

| 探头 | 横向位置 | 用途 |
|---|---|---|
| 最左（GRAY_1） | -43 mm | 辅助识别左侧特征（弯道入口、路口） |
| 中左（GRAY_2） | -15 mm | 主循迹纠偏 |
| 中间（GRAY_3） | 0 mm | 主循迹基准 |
| 中右（GRAY_4） | +15 mm | 主循迹纠偏 |
| 最右（GRAY_5） | +43 mm | 辅助识别右侧特征（弯道入口、路口） |

**线宽约 20 mm（-10～+10 mm）**，所以中间三路（-15～+15 mm）在正常居中时都能检测到黑线，外侧探头主要用于识别偏离主线的事件。

---

## 二、控制分层

### 2.1 层级结构

```
application/app_chassis      底盘任务组织、自动流程状态管理
    ↓
application/app_line_task    循迹任务的流程管理（进入哪条线、何时转弯、何时退出）
    ↓
components/line             算法：偏移计算、转向控制、特征识别
    ↓
bsp_uart / bsp_gpio         硬件：灰度传感器读取
```

### 2.2 职责划分

| 模块 | 职责 |
|---|---|
| **app_chassis** | 知道"现在执行第一段循迹"、"路线号 1/2/3"、"转圈模式" |
| **app_line_task** | 根据当前段和特征，决定"直行"、"左转"、"右转"、"退出" |
| **line** | 提供原始数据（偏移、特征检测）和基础转向角速度，不知道整机状态 |
| **bsp** | 读取五路灰度，返回 0/1 二值结果 |

## 三、中间三路的循迹逻辑

### 3.1 基本流程

```
读取五路灰度 → 计算中间三路偏移 → 转向目标 = kp × 偏移 → 限幅输出
```

**偏移计算**（按 Pololu 方案）：
- 检测到黑色的探头位置求平均
- 例如中左（-15mm）和中间（0mm）检测到黑，偏移 = (-15 + 0) / 2 = -7.5 mm

**转向角速度**：
```
turn_speed = kp × offset_mm，限制在 [-max_turn, +max_turn]
```

**正常循迹时的速度**：
```
forward_speed = CHASSIS_LINE_FORWARD_MPS（配置常数）
```

### 3.2 工作模式

| 读数模式 | 含义 | 转向 |
|---|---|---|
| 中间单独有黑 | 完全对线 | wz = 0 |
| 中左+中间有黑 | 偏右 | wz > 0（左转纠偏） |
| 中间+中右有黑 | 偏左 | wz < 0（右转纠偏） |
| 三个都有黑或都无黑 | 异常（特征消失或过宽） | 待后续处理 |

## 四、外侧探头的特征识别

### 4.1 外侧触发的含义

**最左或最右探头检测到黑色**，可能表示：
- 直角弯道的入口
- 圆形绕障的入口
- T 形路口的支线
- 或仅是一次噪声

**不能仅凭"一次触发"就判断需要转弯**。

### 4.2 外侧确认机制

**连续多次检测到**（例如连续 3 个控制周期），才认为"确实有外侧特征"：

```
if (gray[LEFT] == BLACK)
    left_trigger_count++
else
    left_trigger_count = 0

if (left_trigger_count >= CONFIRM_THRESHOLD)  // 例如 3
    left_confirmed = 1
    reduce_speed()  // 从循迹速度降到转弯速度
```

这样可以过滤掉单次闪烁或传感器噪声。

### 4.3 与中间三路结合

外侧确认后，同时观察**中间三路的变化**：

```
if (left_confirmed)
{
    // 检查中间三路是否正在离开原来的线
    if (middle_three_pattern_changing)
    {
        // 结合行进距离，判断是直角还是渐进弯
        if (distance_since_trigger > MIN_STRAIGHT_DISTANCE)
            can_turn = 1
    }
}
```

这样可以**区分"支路入口"和"主线弯道"**——如果中间三路仍在跟踪直线，那左侧的黑色可能只是支线，不应该转。

## 五、转弯逻辑

### 5.1 直角转弯流程

```
① 外侧确认 + 中间三路检测到方向变化 + 行进足够距离
    ↓
② 设置转弯目标方向，减速执行
    ↓
③ 转弯中验证：
    - 检查旧线是否已离开（中间三路从"有黑"→"无黑"）
    - 检查新线是否已找到（中间三路重新出现"有黑"的模式）
    ↓
④ 稳定在新方向上的线，恢复循迹速度
```

**转弯中的保护**：
- 转弯超时：例如 2 秒未找到新线，停止转弯并报错
- 最大转角：不要无限旋转

### 5.2 速度配置

| 阶段 | 速度 | 备注 |
|---|---|---|
| 正常循迹 | `CHASSIS_LINE_FORWARD_MPS` | 配置值，例如 0.3 m/s |
| 外侧确认后 | 降低到 50~70% | 给转弯反应时间 |
| 转弯中 | 最低速 | 例如 0.1 m/s |
| 转弯完成后 | 逐步恢复 | 用斜坡到正常速度 |

## 六、路口和分支处理

### 6.1 识别路口

**外侧触发 + 对向外侧也触发**（例如左转弯后，右侧外探也检测到黑），可能表示：
- T 字路口（主线前方分支）
- 十字路口

**处理方式**：由 app_line_task 根据当前路线号（1/2/3）决定走哪条支线。

### 6.2 停线识别

五个探头都检测不到黑色（全白），表示到达停线或完全丢线。

**处理**：
- 保持当前方向缓速前进，尝试重新捕获
- 超时后停止，上报异常

---

## 七、圆环（绕障）处理

### 7.1 与直角路口的区别

- **直角**：外侧触发后，中间立刻切换到新方向
- **圆环**：外侧触发后，中间需要逐渐转弯，持续时间长（可能 1~2 秒）

### 7.2 圆环流程

```
① 任务模式设置为"绕圈"
    ↓
② 外侧触发，开始绕圈，记录起始时间/位置
    ↓
③ 持续循迹纠偏，缓速转弯
    ↓
④ 监控行进角度或时间
    当绕过约 180° 后（或行进足够距离），退出绕圈
    ↓
⑤ 恢复正常循迹
```

**关键**：不能只用"外侧再次消失"来判断绕圈完成，因为绕到另一侧时，对侧外探头会再次触发，容易误判。应该用**阶段标志**（"正在绕圈中"）来管理。

## 八、数据结构和状态

### 8.1 灰度读取结果

```
LineInput {
    black[5]        // 五路探头黑色检测结果（0/1）
    sample_valid    // 本次采样是否有效
}
```

### 8.2 循迹任务状态

```
LineTaskState {
    mode            // NORMAL_LINE, TURNING, CIRCLING, STOPPED
    turn_direction  // LEFT, RIGHT, NONE
    turn_start_time // 开始转弯的时刻
    circling_start_time  // 开始绕圈的时刻
    left_trigger_count   // 左侧连续检测计数
    right_trigger_count  // 右侧连续检测计数
}
```

### 8.3 配置参数

```
// 在 app_config.h 中

// 循迹基础参数
CHASSIS_LINE_FORWARD_MPS        // 循迹前进速度
CHASSIS_LINE_KP                 // 偏移→转向的比例系数
CHASSIS_LINE_MAX_TURN_RPS       // 转向角速度上限

// 特征确认阈值
LINE_TRIGGER_CONFIRM_COUNT      // 外侧多少次确认才认定有特征
LINE_MIN_STRAIGHT_DISTANCE      // 判断直角前的最小直行距离

// 转弯保护
LINE_TURN_TIMEOUT_MS            // 转弯超时时间
LINE_CIRCLING_MAX_ANGLE         // 圆环最大转角（用于超时保护）

// 速度控制
LINE_TURN_SPEED_RATIO           // 转弯时的速度比例（相对循迹速度）
```

## 十、关键设计要点

### 10.1 不要快速转弯
外侧触发后立刻快速转，容易转过头或丢线。改为：
- 多次确认
- 减速观察
- 确认后受控转弯

### 10.2 离开旧线再接受新线
转弯中，必须先看到"中间三路从有黑变无黑"，再等待"重新有黑"，才认为找到了新线。这样可以避免刚开始转就误判完成。

### 10.3 圆环需要阶段标志
不能仅用"外侧消失"来判断绕圈完成，需要一个"正在绕圈中"的标志，配合行进距离或时间判断退出。

### 10.4 配置化参数
灰度阈值、触发次数、超时时间都应该提成配置，便于调试和适配不同赛道。

## 十一、后续工作

1. **转向角度计算**：当前假设用中间三路的偏移求平均，实际转向角可能需要根据**探头到车体旋转中心的距离**修正。

2. **外侧触发的边界**：需要上板测试，外侧探头在多大的横向偏移时会触发（取决于传感器感应范围和反光条件）。

3. **路口消歧**：T 形和十字路口如何区分，可能需要视觉或其他传感器配合。

4. **停线和检查线**：赛道中可能有多种停线（完全停、减速停、等信号停），如何区分需要任务上下文。
